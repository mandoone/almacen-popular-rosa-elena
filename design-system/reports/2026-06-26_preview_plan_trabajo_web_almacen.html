Objetivo general

De vitrina a herramienta operativa

La meta es que la página deje de ser solo una vitrina informativa y se transforme progresivamente en una herramienta de apoyo real para el funcionamiento diario del almacén: registrar pedidos, controlar stock, manejar precios, registrar compras, revisar caja y gestionar pendientes.

El trabajo se organiza en 10 fases secuenciales para permitir revisión, validación y avance ordenado hasta llegar a la primera versión operativa completa.

Perfiles de uso

Quiénes usan la web

Compradores / vecinas y vecinos

Ingresan a la web para revisar el catálogo y hacer pedidos desde celular o computador.

  • Ver catálogo y precios actualizados
  • Agregar productos al carrito
  • Elegir forma de pago
  • Confirmar pedido y retirar en fecha de apertura
  • Conocer la historia del almacén y cómo participar

Vendedoras / vendedores

Atienden durante la apertura presencial. Solo acceden a las herramientas necesarias para vender.

  • Buscar y agregar productos a una venta
  • Registrar cantidad y forma de pago
  • Generar comanda automática
  • Descontar stock al confirmar
  • Registrar pendientes (deudas)
  • No tienen acceso a la administración completa

Administradoras / administradores

Gestionan el funcionamiento general del almacén. Acceso completo al sistema.

  • Ver y gestionar pedidos online
  • Editar productos, precios y stock
  • Revisar ventas presenciales y compras
  • Cuadrar caja por apertura
  • Gestionar pendientes por cobrar
  • Configurar datos generales del almacén

Las 10 etapas del proyecto

El desarrollo se divide en fases secuenciales. Las primeras dos ya están completas. La Fase 2 es la prioridad inmediata porque el sistema ya maneja datos reales de personas.

Detalle de avance

Lo que está listo y lo que sigue

Atención: seguridad pendiente

La Fase 2 es prioritaria antes de agregar cualquier función nueva. El sistema ya registra pedidos reales con nombres y teléfonos de compradores. Las rutas /api/admin/* no están protegidas por servidor: cualquier persona que conozca la URL puede leer los datos.

Fase 1 — Base operativa y pedidos reales Completada y probada

Los pedidos ya no dependen del navegador de un computador específico. La tienda genera pedidos reales que quedan registrados en Google Sheets y son visibles desde el panel admin. Flujo completo probado: tienda → pedido → base operativa → admin → stock.

✓ Base operativa en Google Sheets (10 hojas) ✓ 53 productos con códigos PROD-001… ✓ Backend con Apps Script (6 acciones) ✓ Pedidos reales guardados con detalle ✓ Stock descontado al crear pedido ✓ LockService para concurrencia ✓ Cancelar pedido devuelve stock ✓ Panel admin lee pedidos reales ✓ Cambiar estado y estado de pago ✓ Proxy interno: claves nunca van al cliente
Fase 2 — Seguridad del panel admin Pendiente prioritario

Implementar autenticación real en el servidor: sesión con cookie httpOnly, rutas /api/admin/* protegidas, clave fuera del código frontend, inicio y cierre de sesión reales.

Criterios acordados — Fase 4

El sistema de precios

Se definió que el sistema manejará tres valores por producto. El comprador solo ve el precio final de venta; el administrador ve el costo y el sugerido.

Precio costo

Lo que costó el producto al comprarlo. Solo visible para el administrador. Se actualiza al registrar compras y guarda historial.

Precio sugerido

Calculado con margen sobre el costo. El margen puede ser global (10% inicial), por categoría o por producto. Jerarquía: producto > categoría > global.

Precio final de venta

El que ve el comprador. No cambia automáticamente cuando cambia el costo: el producto queda marcado como "requiere revisión" y el admin confirma el ajuste.

¿Qué sigue ahora?
