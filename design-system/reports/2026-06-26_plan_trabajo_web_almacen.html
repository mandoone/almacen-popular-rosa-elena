Objetivo del documento

Este documento presenta el estado de avance y la planificación general del desarrollo de la web del Almacén Popular Rosa Elena Morales.

El plan se organiza por fases, indicando qué etapas ya están completadas, cuáles están pendientes y cuál es el camino propuesto para llegar a una versión operativa completa del sistema.

Objetivo general

La meta es que la página deje de ser solo una vitrina informativa y se transforme progresivamente en una herramienta de apoyo real para el funcionamiento del almacén.

4.2 Precios

  • Calcular precio sugerido.

  • Mostrar al comprador solo el precio final de venta.
  • Mostrar al admin el precio costo y precio sugerido.

  • Permitir cambiar el margen global.

  • Permitir margen específico por producto.

    • margen global.
  • No cambiar automáticamente el precio publicado cuando cambie el costo.
  • Dejar producto como "requiere revisión de precio" cuando cambie el costo.
  • Permitir que el admin confirme o ajuste el precio final.

6.2 Pendientes

Los pendientes son ventas o comandas donde alguien quedó debiendo.

Los pendientes se tratan como cuentas por cobrar. No entran automáticamente como caja real; se muestran como referencia y el equipo decide manualmente si los considera en la caja final para compra.
  • Registrar pendiente por cobrar.

7.2 Caja disponible para compra

El sistema debe poder considerar:

  • saldo en cuenta;
  • efectivo disponible;
  • pendientes por cobrar como referencia;
  • gastos extra;
  • caja final definida por el equipo.
Modelo de referencia:
Caja calculada = saldo en cuenta + efectivo disponible + pendientes por cobrar − gastos extra
Criterio operativo:
Caja final para compra = monto confirmado manualmente por el equipo
  • Registrar saldo en cuenta.
  • Registrar efectivo disponible.
  • Mostrar pendientes por cobrar como referencia.
  • Registrar gastos extra estimados.
  • Calcular caja disponible sugerida.
  • Permitir editar manualmente la caja final para compra.
  • Usar caja final confirmada para diseñar compra.

Síntesis

Existe una primera base técnica funcionando: la tienda puede generar pedidos reales y el panel admin puede visualizarlos.

El avance pendiente consiste en transformar esa base inicial en un sistema operativo más completo para apoyar el funcionamiento diario del almacén: seguridad, productos, precios, stock, comandas, caja, pendientes, compras e historial.

El trabajo se proyecta por fases para permitir revisión, validación y avance ordenado hasta llegar a la primera versión operativa completa.
