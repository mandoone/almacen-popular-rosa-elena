Stack técnico

Cómo está construida la web

Frontend

Next.js 14 App Router con TypeScript 5 y React 18. Estilos con Tailwind CSS 3.4. Fuentes Inter + Playfair Display vía Google Fonts. 6 páginas públicas y 1 panel de administración.

Backend + datos

Google Apps Script como Web App serverless con 6 acciones. Google Sheets como base de datos: planilla BD_WEB_ALMACEN con 10 hojas (PRODUCTOS, PEDIDOS, DETALLE_PEDIDOS, MOVIMIENTOS_STOCK, CONFIG…).

Seguridad y secretos

La URL de la Web App y el token admin viven en .env.local (ignorado por git). El cliente nunca los ve. Proxy interno via route handlers de Next.js. Deuda pendiente: /api/admin/* sin auth de servidor.

Flujo de pedidos

El comprador agrega productos al carrito (localStorage), ingresa nombre y teléfono, y confirma. El servidor registra el pedido real con LockService (concurrencia), descuenta stock, y abre WhatsApp con el número de pedido.

Panel de administración

Login local en /admin. Lista pedidos reales desde Google Sheets, muestra detalle bajo demanda, cambia estado (pendiente → listo → entregado) y estado de pago, cancela con devolución automática de stock.

Design System liviano

design-system/ sin tocar la web: Brand Kit, tokens CSS nativos, template HTML para informes y prompts para Claude. Objetivo: documentos institucionales con identidad visual real del Almacén.

Deudas técnicas

Lo que queda pendiente

Proteger /api/admin/* con autenticación de servidor

Alta prioridad

El panel /admin verifica la contraseña solo en el cliente (JavaScript). Las rutas /api/admin/pedidos y /api/admin/pedidos/[id] son alcanzables desde cualquier herramienta sin token. Cualquier persona que conozca la ruta puede leer nombre, teléfono y total de todos los pedidos.

Impacto: exposición de datos personales de compradores (nombre, teléfono). Prioridad máxima antes de FASE 2.

forma_pago hardcodeada en la tienda

Media

El pedido siempre se registra con forma_pago: 'efectivo_al_retirar'. No hay selector de medio de pago en el formulario. Si en el futuro se acepta transferencia, hay que agregar el control en tienda/page.tsx y la validación en el backend.

Impacto: menor. No bloquea operación actual. Pendiente para FASE 2.

CONFIG de la planilla con datos temporales

Media

La hoja CONFIG en BD_WEB_ALMACEN tiene valores de prueba: número de WhatsApp del almacén, margen por defecto, datos bancarios y fechas de apertura. Estos deben actualizarse manualmente en Google Sheets antes de la primera apertura real.

Impacto: el almacén no puede operar con datos reales hasta completar esto.

Fechas de apertura y número WhatsApp hardcodeados

Media

En src/app/page.tsx la fecha "9 y 23 de mayo" está hardcodeada y desactualizada. El número 56950807172 aparece en tienda/page.tsx y en Footer.tsx. Ambos deberían consumirse desde CONFIG en la planilla.

Impacto: el Home muestra fechas incorrectas a los visitantes.

Conflicto de token --background vs bg-background

Baja

La variable CSS --background definida en globals.css vale #ffffff, pero el token Tailwind background en tailwind.config.ts vale #F9F5FF. El mismo nombre semántico tiene dos valores distintos. No causa bugs visibles hoy pero es una trampa para futuras modificaciones.

Impacto: bajo actualmente. Resolver en FASE 4 (Design System React).

Archivos de fuente Geist sin usar

Baja

src/app/fonts/GeistVF.woff y src/app/fonts/GeistMonoVF.woff existen en el proyecto pero no están registradas en layout.tsx. Son los archivos por defecto del scaffold de create-next-app que nunca se eliminaron. Ocupan 140 KB sin propósito.

Impacto: ninguno funcional. Limpieza de deuda técnica menor.
