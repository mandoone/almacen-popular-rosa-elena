Fase 2 — Seguridad del panel admin

Lista en producción

Riesgos eliminados

Situación anteriorNivelResultado
Contraseña visible en el frontendCríticoRetirada del código cliente.
Sesión basada en localStorageCríticoReemplazada por cookie httpOnly firmada.
Rutas admin sin autenticación realCríticoProtegidas por middleware y sesión de servidor.

Implementación

  • Login y logout administrativos.
  • Cookie segura firmada con HMAC-SHA256.
  • ADMIN_SESSION_SECRET para firma y ADMIN_PANEL_PASSWORD para acceso.
  • Protección de /admin, /admin/* y /api/admin/*.
  • Excepciones controladas para login y logout.
  • Secretos mantenidos fuera del código público.
/admin sin sesión → /admin/login /admin/login con sesión válida → /admin /api/admin/* sin sesión → 401 JSON login correcto → cookie httpOnly firmada logout → cookie eliminada

Fase 3A — Diagnóstico operativo

Próxima prioridad técnica

Antes de avanzar a productos avanzados, caja o panel vendedor, debe verificarse cómo se manejan estados, pagos, cancelaciones, correcciones y stock.

  • Revisar columnas de PEDIDOS, DETALLE_PEDIDOS y MOVIMIENTOS_STOCK.
  • Revisar funciones de crear, listar, actualizar y cancelar pedidos.
  • Revisar rutas API administrativas y frontend admin.
  • Identificar el origen de pagado_efectivo.
  • Confirmar stock al cancelar y reabrir.
  • Proponer modelo mínimo de pedido, pago y método.
  • Definir cambios seguros para Fase 3B.
Entregable: mapa técnico del flujo actual de pedido y propuesta mínima de corrección, sin implementar todavía.
